# Feature Ticket Examples

These examples demonstrate the expected quality, precision, and judgment of feature tickets.

They are not rigid schemas.

Do not copy sections merely because they appear in an example. Include Technical Research, Open Questions, Proposed Architecture, Proposed Contract, and other optional sections only when they materially improve the ticket.

Examples should teach:

- concise but implementation-ready specification
- repository-informed architecture
- explicit ownership and trust boundaries
- concrete, testable acceptance criteria
- research before escalation when technical questions can be resolved
- genuine open questions rather than manufactured uncertainty
- restraint from over-specifying routine implementation details

Prefer the project's current architecture and documentation over assumptions inferred from an example.
